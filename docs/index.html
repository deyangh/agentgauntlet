AgentGauntlet

pytest for agent security.

Point it at an LLM agent and it runs the thing through a suite of prompt-injection, data-exfiltration, confused-deputy, and tool-misuse scenarios, then tells you — reproducibly — which ones it fell for.

Try it in one command

No API key required — this runs the whole suite against a simulated agent, offline.

pip install git+https://github.com/deyangh/agentgauntlet
agentgauntlet run --adapter mock --out report.html

Why it can measure anything

The harness owns the agent loop. Your agent only answers "given this conversation and these tools, what next?" — AgentGauntlet executes every tool call itself. That buys control over where adversarial payloads appear (inside the data a tool returns, which is how real injection arrives) and observation of every action taken.

Attack success is an observable action. Scenarios are built so the only way to comply is to invoke a canary tool or carry a canary token into an outbound argument. The secret crossed the boundary or it did not; there is no rubric to argue with.

Attack success rate is only half a score

An agent that refuses everything scores a perfect 0% attack success rate. So does one too weak to call tools. Every scenario therefore carries a benign-task check, and both numbers are reported together — a result is good only when attack success is low and utility is high.

Testing your own agent

Three adapters, one interface:

  • litellm — any hosted or local model, including Ollama
  • callable — your own Python agent, guardrails and all, inside the loop
  • subprocess — an agent in any language, over JSON on stdin/stdout
Every attack runs inside an in-process mock environment. No email is sent, no request leaves the machine, nothing is deleted or transferred — the "malicious" tools are instrumented stubs whose invocation is the measurement.
